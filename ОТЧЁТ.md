## 3. Роли и права доступа

- Модель `Manager` — профиль менеджера, связан с `User` через `OneToOneField` (`user`), есть `full_name` и `is_active`.
- У заказчика (`Supplier`) — FK `responsible_manager`.
- `scoped_suppliers(request)` — ядро разграничения:
  - суперпользователь видит всех;
  - обычный менеджер видит только своих заказчиков;
  - у чужого заказчика при открытии карточки/редактирования/смены статуса — 404.
- `/admin-panel/` — админка, доступна тем, у кого есть право на панель.
- Публичный список `/` намеренно показывает **всех** заказчиков любому авторизованному пользователю (решение пользователя, зафиксировано в `README.md`).

## 5. Статусы заказчиков

|---|---|
| `new` | новый |

| `decision` | принимается решение |

В модели:

## 7. Ошибка 500 на странице «Менеджеры»

**Симптом:** `/admin-panel/managers/?m=Сидорова%20Анна` падал с
`ValueError: Field 'id' expected a number but got 'Сидорова Анна'`.

**Причина:** шаблон передавал в query-параметр имя, а вьюха ждала число.

**Исправление:**
- ссылки теперь строятся как `?m={{ m.id|urlencode }}` (ID, а не имя);
- нечисловой `m` безопасно редиректит на список менеджеров;
- ФИО резолвится по ID и показывается через `selected_name`.

Проверено 30 сценариями.

## 8. Цветные бейджи статусов

Задача: цвет бейджа должен зависеть от **статуса**, а не от флага `is_active`.

Реализация в `suppliers/models.py`:

```python
STATUS_BADGES = {
    "new": "text-bg-secondary",
    "contact": "text-bg-info",
    "negotiation": "text-bg-primary",
    "decision": "text-bg-warning",
    "order": "text-bg-success",
    "paid": "text-bg-dark",
}
DEFAULT_STATUS_BADGE = "text-bg-light"

def get_status_badge(value):
    return STATUS_BADGES.get(value, DEFAULT_STATUS_BADGE)

# свойство
@property
def status_badge(self):
    return get_status_badge(self.status)
```

Цвета:

| Статус | Класс | Цвет |
|---|---|---|
| новый | `text-bg-secondary` | серый |
| контакт установлен | `text-bg-info` | голубой |
| переговоры | `text-bg-primary` | синий |
| принимается решение | `text-bg-warning` | жёлтый |
| заказ | `text-bg-success` | зелёный |
| оплачено | `text-bg-dark` | чёрный |
| неизвестный | `text-bg-light` | светлый |

В шаблонах бейдж выводится так:

```html
<span class="badge {{ s.status_badge }}">{{ s.status_display }}</span>
```

**Почему именно `text-bg-*`, а не `bg-*`:** классы `text-bg-*` сами подбирают контрастный цвет текста (на жёлтом и зелёном белый текст нечитаем).

Состояние «активен/деактивирован» вынесено в отдельную метку, чтобы при переделке из палитры статусов не потерялась информация:

```html
{% if s.is_active %}
    <span class="badge text-bg-success">активен</span>
{% else %}
    <span class="badge text-bg-secondary">деактивирован</span>
{% endif %}
```

Проверено 49 сценариями (все шесть статусов, список и карточка, неизвестный статус, деактивация).

## 10. Сообщения и шапка

**Alerts.** В `base.html` CSS-класс подбирается по `message.level_tag`:

```django
<div class="alert alert-{% if message.level_tag == 'error' %}danger
{% elif message.level_tag == 'debug' %}secondary
{% else %}{{ message.level_tag }}{% endif %}" ...>
```

- `error` → `alert-danger`;
- `debug` → `alert-secondary`;
- остальные значения уровня — как есть.
- кнопка закрытия `btn-close` + атрибут `role="alert"`.

**Шапка (navbar):**
- ФИО менеджера (если заполнено) + логин, иначе просто логин;
- бейдж «суперпользователь», если `is_superuser`;

## 11. Команда `set_manager_password`

Файл:
`suppliers/management/commands/set_manager_password.py`

Назначение — массовое назначение паролей менеджерам.

### Параметры

| Аргумент | Назначение |
|---|---|
| `usernames` (позиционные, `nargs="*"`) | конкретные логины; если не заданы — все менеджеры |
| `--password <пароль>` | один общий пароль всем указанным |
| `--random` | сгенерировать новый пароль каждому (поведение по умолчанию) |
| `--length <N>` | длина генерируемого пароля (минимум 8, по умолчанию 14) |
| `--dry-run` | только показать, что изменится; в БД ничего не пишется |

### Баги «до»

- `--dry-run` на самом деле **менял** пароль в БД;
- `--password` не сохранял новый пароль;
- `--random` ничего не делал.

### Что исправлено

- `--dry-run` не сохраняет пароли, печатает предупреждение `DRY RUN` и перечень действий;
- `--password` вызывает `user.set_password(raw)` и `user.save(update_fields=["password"])`;
- `--random` работает и печатает сгенерированный пароль один раз;
- `--password` + `--random` вместе — ошибка (`CommandError`);
- `--length < 8` — ошибка;
- слабые пароли отклоняются через `validate_password` (стандартные валидаторы Django);
- неизвестный логин — понятная ошибка;
- суперпользователь не затрагивается;
- нет менеджеров — подсказка про `seed_managers`.

### Проверка и применение

- 24 сценария на временной SQLite — все зелёные.
- Live: пароль менеджера `petrov` перевыпущен рабочей командой; старый общий пароль (шаблон `manager123`) больше не подходит; группа «Менеджеры» сохранена.

**Запуск — только из корня проекта:**

```powershell
# из C:\Users\Defen\OneDrive\Документы\GitHub\CRM\crmsite
python manage.py set_manager_password petrov
python manage.py set_manager_password --dry-run          # ничего не меняет
python manage.py set_manager_password --password "Новый-пароль"
python manage.py set_manager_password --random --length 20
```

Частая ошибка — запуск из `...\crmsite\crmsite` (`manage.py` там нет). Правильно — либо `cd ..`, либо `python ..\manage.py`.

Пароли выводятся в консоль один раз и в репозиторий не сохраняются.

## 16. Открытые вопросы (не менять без отдельного решения)

1. **Неактивный текущий менеджер при редактировании.** В `SupplierForm` поле `responsible_manager` фильтруется `Manager.objects.filter(is_active=True)`. Если заказчика редактирует суперпользователь, а текущий менеджер стал неактивным, он может выпасть из списка и потеряться при сохранении.
2. **Цикл входа без профиля `Manager`.** Любой пользователь без профиля может получить `/login/ ↔ /admin-panel/`. Сейчас обойдено удалением `guest1`.
3. **`login.html`** с собственным `<style>` — кандидат на унификацию с Bootstrap.
4. **Старые GET-фильтры статусов** (`?status=оплачено`) игнорируются без редиректа.
