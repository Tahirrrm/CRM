# CRM — веб-интерфейс на Django + PostgreSQL

CRM веб-приложение для учёта заказчиков на Django и PostgreSQL.

Таблица заказчиков содержит колонки: Регион, Город, ФИО, Организация, телефон, статус, e-mail, ответственный менеджер.
Статус: новый, контакт установлен, переговоры, принимается решение, заказ, оплачено.

## Функции
- Просмотр списка заказчиков
- Создание заказчика
- Просмотр карточки заказчика
- Редактирование заказчика
- Изменение статуса
- Деактивация заказчика
- Кастомная админ-панель `/admin-panel/`: дашборд, календарь, менеджеры, заказчики (CRUD)
- Стандартная админка Django `/admin/` с фильтрами и поиском (только суперпользователь)
- Отдельная страница входа `/login/`
- Роли: суперпользователь видит всех; менеджер видит и редактирует только своих заказчиков

### Права доступа
Вход для всех — на странице `/login/`.

**Суперпользователь** (`is_superuser`): стандартная админка Django `/admin/` (пользователи,
менеджеры, все заказчики) плюс `/admin-panel/`.

**Менеджер** (`is_staff=False`, группа «Менеджеры» с правами `view_supplier` и `change_supplier`):
доступна только `/admin-panel/`. В стандартную админку Django попасть не может — все разделы
закрыты, попытка перенаправляет на `/login/`. Видит и редактирует только своих заказчиков,
чужие не отображаются в списках и открываются с 404. Ответственного менеджера у заказчика
изменить не может, удалять заказчиков и менеджеров не может. Разделы «Пользователи», «Группы»
и «Менеджеры» в стандартной админке скрыты от менеджера полностью.

Ответственный менеджер хранится связью с профилем `Manager`, а не строкой с ФИО, поэтому
переименование менеджера не «теряет» его заказчиков, а удаление профиля оставляет заказчиков
в базе с пустым ответственным (`on_delete=SET_NULL`).

### Смена паролей менеджерами
```bash
python manage.py set_manager_password                    # новый случайный пароль каждому менеджеру
python manage.py set_manager_password petrov kozlov      # только выбранным
python manage.py set_manager_password petrov --password 'свой-пароль'
python manage.py set_manager_password --dry-run          # показать, не меняя
```
Каждому менеджеру генерируется свой пароль, все они печатаются один раз. Пароли проверяются
стандартными валидаторами Django (минимум 8 символов, не только цифры, не похож на логин),
поэтому слабый пароль команда не примет. Суперпользователей команда не трогает.

## Запуск

### 1. Запустить PostgreSQL (Docker)
```bash
docker run --name crm_db -e POSTGRES_DB=crm_db -e POSTGRES_USER=crm_user -e POSTGRES_PASSWORD=crm_pwd -p 5436:5432 -v crm_data:/var/lib/postgresql/data -d postgres:16
```

### 2. Настройки БД
Параметры подключения не захардкожены: `crmsite/settings.py` читает их из файла `.env` через `django-environ`
(`DATABASES = {'default': env.db()}`).

Создайте `.env` в корне репозитория рядом с `manage.py`:

```ini
SECRET_KEY=замените-на-случайную-строку
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost
DATABASE_URL=postgres://crm_user:crm_pwd@localhost:5436/crm_db
```

Формат `DATABASE_URL`: `postgres://<USER>:<PASSWORD>@<HOST>:<PORT>/<NAME>` — значения соответствуют команде из шага 1.

Файл `.env` содержит секреты и не должен попадать в git (он добавлен в `.gitignore`).

> В django-environ 0.14+ вызов `read_env()` без аргумента ищет `.env` только в каталоге файла, который его вызвал,
> то есть в `crmsite/`, а не в корне проекта. Поэтому в `settings.py` путь передаётся явно:
> `environ.Env.read_env(BASE_DIR / '.env')`. Без этого `manage.py` падает с
> `ImproperlyConfigured: Set the SECRET_KEY environment variable`.

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Миграции, начальные данные и запуск
```bash
python manage.py migrate
python manage.py createsuperuser   # логин/пароль для админки
python manage.py seed_managers     # создать менеджеров (каждому свой пароль, печатается один раз)
python manage.py seed_suppliers    # (опционально) 50 демо-заказчиков
python manage.py runserver
```

`seed_suppliers` требует, чтобы менеджеры уже были созданы — заказчики привязываются к их профилям.
Пароли, напечатанные `seed_managers`, сохраните: в базе хранится только хеш, восстановить их
нельзя, при потере выдайте новые через `set_manager_password`.

Вход: http://127.0.0.1:8000/login/
Сайт: http://127.0.0.1:8000/
Админ-панель: http://127.0.0.1:8000/admin-panel/
Стандартная админка (только суперпользователь): http://127.0.0.1:8000/admin/

Если порт 8000 занят: `python manage.py runserver 127.0.0.1:8001`
